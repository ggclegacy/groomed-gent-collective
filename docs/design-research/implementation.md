# Living Instrument implementation

The research-led visual thesis is implemented in `app/spatial-system.css`, loaded after prior styles as the authoritative material system. Existing workspace markup and user workflows remain intact. `SpatialCommand` replaces the previous personal Command composition with a compact greeting, actual priorities, a CSS 3D Cassius instrument and three connected destination surfaces. Financial/demo data remains owned by the existing dashboard.

Motion uses CSS transforms plus one shared pointer listener with requestAnimationFrame. Selected cards use a bounded ±2-degree response; inputs and focused surfaces are excluded. Shadows and edge lighting communicate depth. Ambient layers and the instrument use slow transforms, not a continuous canvas renderer or animated blur. No new package, WebGL runtime, image download or remote font is needed.

The motion preference remains local to the device. Reduced-motion and fine-pointer checks suppress spatial response; pause, visibility, focus and pointer exit clear movement. Intersection visibility pauses offscreen material animation. Reduced transparency, high contrast and forced colors have explicit fallbacks. Text is readable independently of the decorative instrument. This is a browser interpretation, not Apple's native Liquid Glass renderer.

Private memory is unchanged. Counts come from real records, with no invented presence/AI connectivity. The instrument invokes the existing reviewed Cassius prompt. No analytics event or engagement tracking was added. No attention score, fake streak, scarcity mechanism or external message was added.

The source also contained newer Voyage work. It was preserved; an existing literal-type inference error in its explicit taste-event source was narrowed, and an older reverse-lookup test was corrected to issue the reverse query after the handler gained a forward-search mode. The test assertions remain intact.
