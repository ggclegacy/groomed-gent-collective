# Gentleman OS — first implementation slice

## Architecture and plan

Extend the latest `visual-dashboard-work/app` source. Preserve ambassador routes, account services, Product Studio, Creator Studio, knowledge policies and performance dashboard. This mirror has no Git history; other `*-work` folders are earlier snapshots and remain untouched.

1. Six primary environments, with legacy destinations retained under Collective and supporting Desk / Vault / Logbook / Profile destinations.
2. Shared in-memory working state, explicit authenticated account saves, private versioned data contract and additive D1 migration.
3. Persistent Cassius drawer with opt-in, bounded cross-module context. No automatic memory writes or action execution.
4. Trip planning brief and AI itinerary draft; relationship capture and meeting preparation; grooming routines and personal presentation records; tasks, decisions, references and private notes. Command derives priorities from actual entered records.
5. Verification of validators, consent, ownership, conflicts, existing tests and production compilation.

## Decisions

Private memory is a separate member-owned document, never stored in ambassador draft libraries or browser storage. `gentleman_memories.owner_id` references members. All reads and writes require the existing trusted identity dispatcher and active membership. Writes use revision compare-and-swap. Account data is never sent to Cassius automatically. Profile and individual records have separate opt-ins, off by default. Unchecked records are excluded at request construction. Model requests use existing server limits, same-origin checks and `store:false`.

Next.js deliberately fails closed without trusted identity and a database; no invented local identity or public header authentication was added. The interface permits temporary working drafts and labels unsaved state. Sites uses existing D1 runtime. Deploy the additive migration before enabling account storage. No production database was changed by source edits.

V1 records use typed kinds and explicit dates, completion, consent and travel mode. Trip itinerary prose is editable and marked unverified; booking, current opening hours, live flights and pricing are not implied. A future normalized itinerary table can migrate the versioned document. Profile membership role and financial facts must eventually come from authoritative member/performance services, never editable personal profile fields.

## Flags / integration gates

`CASSIUS_ENABLED=false` disables existing AI requests. Missing `OPENAI_API_KEY` produces a connected-service error, never fake generated output. Personal storage is gated by the existing trusted identity mode, active membership and D1 binding. No separate public-preview bypass exists. New navigation is enabled in this source build.

## Deferred / next sequence

- Wire and verify the production identity/database adapter on the chosen deployment; verify cross-account isolation in that environment.
- Authenticated structured AI trip generation with schema-constrained day/event output, timezone-aware itinerary editing, meeting anchors and verified city sources.
- Dedicated server-resolved context retrieval with per-request scopes, per-member rate limits, provenance, audited tool actions and durable request IDs. Current selected context is client-supplied reference data, never authority.
- Contact entity extraction with review/merge, recurring follow-ups and opt-in calendar connection.
- R2 document uploads with malware scanning, short-lived owner-authorized access and extraction consent. Vault currently stores text references only; no file-upload claim.
- Voice transcription with consent, member business brand-kit integration in Creator Studio, wardrobe images, Places search and opt-in Collective networking.
- Encryption-key strategy, retention/backup deletion policy and audit metadata before broader rollout. Ordinary account storage is not end-to-end encryption.
